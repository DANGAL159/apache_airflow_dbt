Actividad

El estudiante debe crear, ejecutar y validar un pipeline de datos con Apache Airflow y dbt, utilizando como base el repositorio apache_airflow_dbt. La dinámica consiste en trabajar en una rama propia, comprobar el pipeline en un entorno local con Docker y entregar los cambios mediante un pull request.

Para desarrollar la actividad, el estudiante debe:

  1. Crear un fork del repositorio y abrirlo en GitHub Codespaces. Crear una rama con el nombre entrega/TU_CARNET.
  2. Activar el entorno con source .venv/bin/activate y ejecutar python scripts/crear_dag.py TU_CARNET, sustituyendo TU_CARNET por los nueve dígitos de su carnet. El archivo debe quedar en dags/TU_CARNET_airflow_dbt.py, con el identificador estudiante_TU_CARNET_dbt.
  3. Revisar las tareas de carga, transformación y validación. Agregar en verificar_ventas una comprobación SQL que confirme que la suma de monto_neto es 3766.75, además de las comprobaciones de conteo y unicidad existentes. Conservar el esquema alumno_TU_CARNET asignado a su DAG.
  4. Ejecutar python scripts/validar_dags.py, corregir los errores encontrados y subir los cambios a su rama. Clonar en su equipo el repositorio completo de su fork y seleccionar esa misma rama para realizar la prueba local.
  5. Con Docker Desktop iniciado y utilizando contenedores Linux, entrar a la carpeta local/ y ejecutar docker compose up. Esperar la inicialización y abrir http://localhost:8084 con el usuario admin y la contraseña admin, correspondientes únicamente al entorno local.
  6. Habilitar y ejecutar su DAG. Verificar que las cuatro tareas finalicen en success y que dbt apruebe sus 38 pruebas. Ejecutar el pipeline una segunda vez y comprobar en su tabla alumno_TU_CARNET_marts.fact_ventas que permanecen 10 ventas, 10 identificadores únicos y un total neto de 3766.75.
  7. Abrir un pull request desde su rama hacia SS2-USAC/apache_airflow_dbt:main. Incluir su carnet y explicar la validación agregada. El check validate debe terminar correctamente. Después de la revisión y fusión por parte del docente, GitHub Actions publicará el DAG en el Airflow del curso en GCP.

Como evidencia final, el estudiante debe mostrar su DAG ejecutado correctamente en Airflow y presentar en un bloc de notas su carnet, junto con la hora visible del sistema. En las capturas debe observarse claramente:

  • El entorno local iniciado y el DAG del estudiante con sus tareas completadas correctamente.
  • La validación de datos y la segunda ejecución sin duplicados.
  • El bloc de notas con el carnet del estudiante.
  • La hora del sistema visible en la pantalla.

La actividad busca comprobar que el estudiante puede levantar el entorno, adaptar un DAG, validar sus resultados y participar en un flujo de entrega colaborativo. La entrega se realiza con el PR abierto y el check aprobado; la revisión, fusión y ejecución en GCP corresponden a la etapa posterior coordinada por el docente.

Evidencia solicitada

Capturas de pantalla y enlaces mostrando:

  • Salida de docker compose ps -a: los servicios permanentes activos y los servicios prepare y airflow-init finalizados con código 0.
  • El grafo de estudiante_TU_CARNET_dbt con sus cuatro tareas en success y las dos ejecuciones exitosas.
  • El log de dbt con las pruebas aprobadas y la consulta SQL posterior a la segunda ejecución, mostrando 10 ventas únicas y total neto 3766.75.
  • El enlace al pull request, el check validate aprobado y una explicación breve de la validación SQL agregada.
  • Carnet escrito correctamente en un bloc de notas y hora visible del sistema en las capturas de ejecución.
