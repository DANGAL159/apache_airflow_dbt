Actividad

El estudiante debe ejecutar y revisar el pipeline de ejemplo de Apache Airflow y dbt del repositorio apache_airflow_dbt.

Entorno de trabajo:

  • Fuera de clase: descargar o clonar el repositorio completo, iniciar Docker Desktop y ejecutar docker compose up desde la carpeta local/. Abrir http://localhost:8084 con usuario admin y contraseña admin.
  • Durante la clase: crear un fork del repositorio, preparar un DAG propio y entregarlo mediante un pull request (merge request) para ejecutarlo en el entorno cloud del curso. No es necesario instalar Docker para esta modalidad.

Preparación durante la clase: abrir el fork en GitHub Codespaces y ejecutar los siguientes comandos, sustituyendo TU_CARNET por su carnet numérico completo:

source .venv/bin/activate
git switch -c entrega/TU_CARNET
python scripts/crear_dag.py TU_CARNET

Editar únicamente dags/TU_CARNET_airflow_dbt.py. En la tarea verificar_ventas, agregar a la consulta SQL la comprobación SUM(monto_neto) = 3766.75, conservando las comprobaciones de conteo y unicidad. Mantener el carnet, el esquema propio y las dependencias generadas. No modificar los DAGs de ejemplo, los archivos dbt ni la configuración del entorno.

Validar y subir el archivo modificado:

python scripts/validar_dags.py
git add dags/TU_CARNET_airflow_dbt.py
git commit -m "Agregar DAG de TU_CARNET"
git push -u origin entrega/TU_CARNET

Abrir un pull request hacia SS2-USAC/apache_airflow_dbt:main que incluya el archivo dags/TU_CARNET_airflow_dbt.py y esperar que el check validate apruebe. El docente revisará y fusionará el cambio, iniciará las ejecuciones en cloud y proporcionará el acceso para consultar los resultados.

Realizar los siguientes pasos en el entorno correspondiente:

  1. Abrir el DAG s8_dbt_sgfood en local o estudiante_TU_CARNET_dbt en cloud e identificar sus cuatro tareas y el orden en que se ejecutan.
  2. Ejecutar el DAG en local o seguir la ejecución dirigida en clase. Comprobar que las tareas finalicen en success y revisar el log de dbt con sus 38 pruebas aprobadas.
  3. Repetir la ejecución y revisar la tarea de validación para comprobar que se mantienen 10 ventas sin duplicados.
  4. Explicar brevemente para qué sirve Airflow en este ejemplo y qué ocurre si una tarea falla.

Evidencia solicitada

Entregar las siguientes capturas y una explicación breve, usando el entorno local o el cloud de la clase:

  • Solo para la modalidad de clase: enlaces al fork y al pull request que contiene su DAG con la validación del total neto, con el check validate aprobado.
  • El DAG con sus cuatro tareas en success y las dos ejecuciones exitosas.
  • El log de dbt con las pruebas aprobadas y la tarea de validación exitosa después de la segunda ejecución.
  • Una explicación de tres a cinco líneas sobre la función de Airflow y el efecto de una falla en el pipeline.

En las capturas debe aparecer el carnet del estudiante en un bloc de notas y la hora visible del sistema.
